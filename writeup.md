# Writeup

## What I Cut and Why
The main items I removed were the conditional schema rule, an automated step to write the agent’s generated code into `pipeline.py`, and extra failure cases beyond one type error. Originally, `chief_complaint` and `duration` were only required when `visit_type` was a sick visit, and `rx` was excluded, since the note is written before a provider prescribes anything. I cut this for a simpler type mismatch (`age` as a `string`) instead. The conditional version would have shown how a schema can require different fields depending on another field’s value. It was the more interesting idea, but I simplified it to make the schema and repair loop easier for a beginner to understand and help the course fit the 90-minute target. For the agent, I move its generated code into `pipeline.py` by hand, rather than automatically writing it to the file, since I prioritized the builds compounding correctly over full automation.

## Where My Course Is Weakest
The weakest part of my course is the generation and review process. Courses were generated one section at a time, and code was used to check basic requirements (like word count). I also manually read each generated section to check technical correctness and whether it followed the intended lesson structure. When I found an issue, I updated the `core_idea` or `avoid` instructions in `sections.py` and regenerated that section. This worked for a course with only eight sections, but it wouldn’t scale well as the number of sections and courses grows. With more time, I would add a generator-critic workflow, where a second model acts as a critic and reviews each generated section against its checkpoints, technical requirements, and section boundaries. If a problem is found, the critic’s feedback could automatically be sent back to the generator for another attempt. Deterministic checks, like word count, would still remain in code.
